# 历史流水、关联事项与提醒收起

## 需求与交互

1. **历史流水**默认显示全部日期的记录，最新日期排在前面。列表带日期列，可搜索内容或标签、查看全文及复制。点击日期按钮筛选一天，点击「查看全部」清除日期限制；搜索条件保留。
2. **筛选日历**只高亮并开放有记录的日期，无记录日期为灰色禁用。月份下拉及前后按钮在有记录的月份之间切换，方便定位很久以前的记录。补记和编辑的日期控件仍允许任意日期，以便补录尚无记录的日期。
3. **跨天续记**在提醒卡片点击「全部历史 / 续记」，或在补记窗口点击「从全部历史记录选择…」。选择已有事项会填入内容、标签；保存生成独立的新流水，保留新的日期与时间。
4. **关联编辑**保留今日、历史流水双击编辑入口，并在提醒卡片的今日列表增加「编辑」「复制」。同一事项有多条记录时，编辑窗口默认勾选「同步修改同一事项」，显示影响数量。同步只修改内容、标签，各条日期、时间、来源及续记出处保留；日期和时间的修改只应用当前条。取消勾选可以只改当前条。
5. **临时收起提醒**点击「去其他应用复制 / 查看」后，各屏幕的卡片和背景遮罩均隐藏；一个可拖动、可最小化的小窗口保留返回入口、当前内容复制及历史选择。其他应用可以正常操作。点击「返回提醒」或关闭小窗口后恢复全部提醒卡片，输入、标签、隐私开关和倒计时状态保留。此操作不计为跳过、推迟或活动完成，也不保存新流水；原有关闭动作继续负责保存。

## 数据关联与兼容

每条流水仍存独立日期、时间和内容，增加稳定的 `work_item_id` 字符串作为事项标识。使用独立标识而非最早记录 ID，删除首条记录后其余记录仍关联。

首次升级在一个事务中增加字段和索引，并依据已有 `continue_from` 链及相同非空内容补齐关联。处理续记环和已删除出处，不改写旧流水内容、时间。之后启动不重复归组，保留用户单独修改的结果。

新增时，内容与所选事项相同则复用关联；手动输入相同内容也自动关联。内容匹配忽略两端空白，正文其余字符精确匹配；相似项目名称不会自动合并。选择历史后改写成不同内容会作为另一事项保存。

同步编辑在同一个 SQLite 事务中更新关联记录的内容和标签，再更新当前条的日期和时间；任一写入失败全部回滚。关联查询也纳入完全相同内容的记录，确保历史中同内容记录一起修改。单条修改内容时分配新的事项标识，与原关联分离。

流水变化通知在事务提交后发布；今日、历史、选择器和提醒卡片即时刷新。已经填入提醒输入框的事项被修改时，仅更新仍未被用户改写的草稿，避免覆盖正在输入的内容。

备份、导出数据库和数据目录迁移继续采用完整 SQLite 复制，新字段随库保留。日报、周报继续读取流水；已经导入的报告是保存的独立成品，需要原有「重新复制提示词+最新数据」流程重新生成。

自动回归覆盖：全部/单日查询、有效日期去重、跨天续记、相同与相似内容、同步范围与独立时间、删除首条、单条分离、事务失败回滚、旧库升级及重启、迁移后关联、日历禁用与跨月、内容/标签搜索、数据变化刷新、多屏收起、收起期间屏幕重建、返回后草稿与关联保存。实际显示器热插拔和跨屏 DPI 仍可按测试清单复核。
