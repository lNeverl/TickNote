- 版本：V2.2（明确数据层次；补充竞品调研与高 DPI 适配）
- 日期：2026-09-14
- 目标平台：Windows 10/11 64 位，单 EXE 桌面程序
- 用户背景：汽车发动机控制器嵌入式软件开发工程师，双显示器工作环境
- **关键约束：用户电脑内存紧张，低内存占用是一票否决级的硬指标**
- 开发方式：AI Coding（用户本地搭建一次开发环境，AI 负责全部编码与打包；同时保留人类可维护、可手工编译的标准工程结构）

## 1. 项目概述

### 1.1 要解决的痛点

1. **久坐不动**：长时间盯屏幕写代码/查故障，缺乏起身活动的提醒。
2. **忘记写日报**：下班时想不起来白天做了什么。
3. **杂活无法体现工作量**：嵌入式开发中大量工作是故障调查、协助他人、功能评估等"杂事"，不体现在 git 提交里，日报/周报难写。

### 1.2 核心设计思路

把"久坐提醒弹窗"和"工作流水记录"两个需求合并：

> 每隔 N 分钟（默认 50 分钟，可配），在所有显示器上弹出全屏遮罩提醒窗口，提示用户起身活动；弹窗上提供输入框 + 今日已有流水列表，用户顺手写一句"在做什么"，或者**一键点击今天之前的某条记录表示"还在做这件事"**。每条记录自动带时间戳，一天下来工作流水自动串起来；每天/每周可将流水连同固定提示词一键复制给 AI，生成正式日报/周报后粘贴回软件保存。

弹窗是强制的（全屏覆盖），既解决了"提醒被忽略"，也利用这个强制触点把"随手记"变成零成本动作。

### 1.3 名词定义

| 名词 | 含义 |
|---|---|
| 提醒周期 | 两次弹窗之间的工作间隔，默认 50 分钟，可配 |
| 活动时长 | 弹窗出现后建议的起身活动时间，默认 5 分钟，可配 |
| 工作流水 | 带时间戳的"正在做什么"原始记录条目（原料数据） |
| 日报/周报 | 由 AI 根据流水生成、粘贴回软件保存的正式报告（成品数据） |
| 数据目录 | 存放数据库与所有配置的文件夹，由首次运行向导决定 |
| 便携模式 | 数据目录 = EXE 所在目录下的 `data\` 子目录，整体拷贝即用 |

## 2. 技术框架评估与选型（V2 定稿：内存优先）

### 2.1 候选方案对比（以常驻内存为核心指标）

| 方案 | 常驻内存 | EXE 体积 | AI Coding 友好度 | 全屏多屏 | 托盘/自启 | 结论 |
|---|---|---|---|---|---|---|
| **C# + WinForms + .NET 8** | **约 25–50 MB** | 自包含单文件约 65 MB | **极高**（AI 对 C# 支持最好之一） | `Screen.AllScreens` 逐屏建无边框窗体 | NotifyIcon / 注册表，极成熟 | **推荐** |
| C# + WPF + .NET 8 | 约 50–80 MB | 同上 | 极高 | 支持，透明动画更漂亮 | 同上 | 备选（界面更炫但内存翻倍） |
| Python + PySide6 | 约 80–120 MB | 40–80 MB | 高 | QScreen 支持好 | 成熟 | **排除（内存超标）** |
| Go + walk | 约 15–30 MB | 约 10 MB | 中（GUI 库小众，AI 易出错） | 需手写较多 | 支持 | 排除（开发摩擦大，容易烂尾） |
| Electron / Tauri | 100 MB+ / 依赖 WebView2 | — | — | — | — | 排除 |

### 2.2 最终选型：C# + WinForms + .NET 8

**理由：**

1. **内存达标**：.NET 8 的 WinForms 常驻约 25–50 MB，是"AI 友好 + 低内存"的最优平衡点。Go 虽然更省，但 GUI 生态小众，AI 生成代码出错率高、调试成本大，违背"可靠、能落地"的目标。
2. **AI Coding 友好度最高**：C#/WinForms 是所有主流 AI 最擅长的桌面技术栈之一，需求文档可以直接喂给 AI 开发。
3. **UI 全部用纯 C# 代码编写**：WinForms 界面就是普通的 C# 类代码（`new Button()`、设属性、摆布局），**不需要 XAML**（XAML 是 WPF 的标记语言），也不依赖 Visual Studio 设计器生成的文件，AI 可以完整、可控地写出全部界面，人类读代码也能看懂。
4. **功能全覆盖**：多屏枚举（`Screen.AllScreens`）、无边框全屏窗体 + `Opacity` 半透明遮罩、托盘 `NotifyIcon`、注册表自启、空闲检测（`GetLastInputInfo`）、锁屏检测（`SystemEvents.SessionSwitch`）全部有成熟写法。
5. **单文件发布**：`dotnet publish -r win-x64 --self-contained -p:PublishSingleFile=true` 产出单个 EXE，双击即用，目标机无需装任何东西。

**技术栈清单：**

| 用途 | 选型 |
|---|---|
| 语言 / 框架 | C# 12 / WinForms / .NET 8 |
| UI 编写方式 | 纯 C# 代码 + 布局容器（TableLayoutPanel / FlowLayoutPanel），不使用 XAML、不依赖 VS 设计器 |
| DPI 模式 | PerMonitorV2（多屏不同缩放比下不变形） |
| 数据存储 | SQLite（`Microsoft.Data.Sqlite`），单文件本地库 |
| JSON 序列化 | `System.Text.Json` |
| 开机自启 | 注册表 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` |
| 空闲检测 | Win32 `GetLastInputInfo`（P/Invoke） |
| 锁屏检测 | `Microsoft.Win32.SystemEvents.SessionSwitch` |
| 剪贴板交互 | `Clipboard.SetText` / `GetText`（AI 导入导出） |
| 打包发布 | `dotnet publish` 自包含单文件 |
| 数据目录 | 首次运行向导决定（见 M0），默认 `%APPDATA%\SedentaryReminder\` |

### 2.3 开发环境（用户一次性搭建，极简）

**只需要装一个东西，不需要 Visual Studio：**

1. 打开官网 <https://dotnet.microsoft.com/zh-cn/download>，找到 **.NET 8.0**（不要选更新的版本）。
2. 下载 **SDK** 的 **Windows x64 Installer**（注意：是 SDK 不是 Runtime，是 x64 不是 Arm64），双击一路下一步。
3. 验证：打开终端执行 `dotnet --version`，显示 `8.x.x` 即成功。

> **为什么选 .NET 8 而不是 .NET 10**：.NET 8 是 LTS 长期支持版，最成熟稳定，且 AI 对 .NET 8 的代码模式最熟悉、出错率最低；.NET 10 对本项目没有任何收益。（.NET 10 SDK 也能编译本项目，装了不算错，但没必要。）
>
> **运行本软件的电脑需要装框架吗？——完全不需要。** 本项目采用自包含单文件发布（`--self-contained`），打包时 .NET 运行时已内嵌进 EXE。最终 EXE 拷到任何 Windows 电脑双击即跑，目标机零依赖。**只有开发/打包的那台电脑需要装 SDK，且只需装一次。**

> 关于"C# 有两个环境"的说明：历史上存在 **.NET Framework**（4.x，2002 年起的老框架，Windows 自带，已停止演进）和现代的 **.NET**（5/6/7/8，原名 .NET Core，开源、跨平台、微软当前主力）。本项目用的是现代 **.NET 8** ——装上面这一个 SDK 就完事，编译、打包、运行全由命令行 `dotnet` 完成，**不需要 Visual Studio 等任何其他东西**。

其余全部（建项目、写代码、装 NuGet 包、打包 EXE）由 AI Coding 完成。生成的最终 EXE 拷贝到任何 Windows 电脑都能直接运行，不依赖 .NET 环境。

### 2.4 人类可维护性要求（留给"人"的接口）

即使全程 AI 开发，工程必须保证任何开发者（或未来的 AI）拿到源码后能正常编译导出：

| 编号 | 要求 |
|---|---|
| H1 | 标准 .NET 工程结构：`SedentaryReminder.sln` + `src/SedentaryReminder.csproj` + 按模块分文件夹（`Reminder/`、`Overlay/`、`Log/`、`Report/`、`Settings/`、`Data/`） |
| H2 | 不依赖 Visual Studio 专有功能：UI 用手写布局代码（必须是人可读的手写代码），不用设计器生成的 `.Designer.cs`，不用 `.resx` 二进制资源 |
| H3 | UI 布局必须使用布局容器（TableLayoutPanel/FlowLayoutPanel/Dock/Anchor），禁止逐控件绝对坐标摆位——保证改一处不牵连全局、适配不同 DPI 和窗口尺寸 |
| H4 | 仓库根目录提供 `build.bat`：双击即执行 `dotnet publish` 输出单文件 EXE 到 `dist\` |
| H5 | 仓库根目录提供 `README.md`：写明环境要求（只需 .NET 8 SDK）、编译命令、打包命令、目录结构说明 |
| H6 | 代码内注释只写"为什么"，公开 API 有 XML 注释摘要 |

> **关于"纯代码写 UI 是否不利于人类维护"的结论**：恰恰相反。在没有 Visual Studio 的环境里，设计器生成的 `.Designer.cs` 文件手工编辑极易损坏且无法可视化预览；而配合布局容器的手写 UI 代码，人和 AI 都能直接读、直接改、diff 清晰。历史上"设计器优于手写"的观点（如 StackExchange 上的讨论）前提是开发者有完整 Visual Studio，本项目的约束（无 VS、AI 主导）下手写代码是更可维护的选择。

## 3. 功能需求（详细）

### 3.1 模块划分

```
软件
├── M0 首次运行向导与便携模式
├── M1 定时提醒引擎
├── M2 全屏提醒弹窗（多屏，双屏均可输入）
├── M3 工作流水记录（含一键续记）
├── M4 日报/周报生成（AI 复制粘贴闭环）与导出
├── M5 系统托盘与设置
└── M6 数据存储与迁移
```

### 3.2 数据层次总述（一套库、两类数据、两个视图）

**用户关心的"随手记 vs 正式报告是不是两套数据库、两个界面"——设计定稿如下：**

- **一套数据库**：全部数据在同一个 `data.db` 文件里，不分两个库。
- **两类数据**（两张表，职责不同）：
  - `work_log` 原始流水：弹窗随手记的原料数据，零散、口语化、可编辑。
  - `report` 正式报告：AI 生成后粘贴回来的成品，按"日/周"归档。
- **两个视图**（两个界面，入口都在托盘菜单）：
  - **流水视图**（"查看今日"/"历史流水"）：按时间轴展示和编辑原始流水。
  - **报告视图**（"我的日报/周报"）：按日期/周归档展示正式报告，可查看、编辑、一键复制全文去提交。
- **两者的关系**：报告由流水生成，但**生成后独立保存、互不同步**——事后修改流水不会自动改报告；如需更新报告，报告视图提供"重新复制提示词+最新数据"按钮，再走一遍 AI 流程粘贴回来覆盖。这样保证：原始素材永远完整保留，正式报告永远是你确认过的版本。

### M0 首次运行向导与便携模式

| 编号 | 需求 | 说明 | 优先级 |
|---|---|---|---|
| M0-1 | 首次运行向导 | 首次启动（EXE 旁无引导配置时）弹出向导，让用户选择数据保存位置 | P0 |
| M0-2 | 选项 A：便携模式 | 数据保存在 **EXE 所在目录下的 `data\` 子目录**。整个文件夹（EXE + data）拷到 U 盘/网盘/别的电脑，双击即用，数据完整不丢 | P0 |
| M0-3 | 选项 B：自定义目录 | 用户选一个文件夹（如 `D:\我的数据\SedentaryReminder` 或 `%APPDATA%\SedentaryReminder`）。**所有配置文件、数据库、生成的报告全部只放这个目录**，软件目录不留任何用户数据 | P0 |
| M0-4 | 识别已有数据目录 | 向导选择目录时，如果该目录里已存在本软件的数据（检测到 `data.db`），提示"检测到已有数据，将直接接管使用"，实现**换电脑后指向老文件夹 = 完整恢复环境** | P0 |
| M0-5 | 引导配置文件 | 选择结果记录在 **EXE 旁的 `boot.config.json`**（仅一行数据目录路径）。它是唯一放在 EXE 旁的文件；之后每次启动读它定位数据目录 | P0 |
| M0-6 | 引导文件丢失处理 | `boot.config.json` 丢失或指向路径不存在时，重新走首次向导（不报错崩溃） | P1 |
| M0-7 | 设置中更换数据目录 | 设置界面提供"更换数据位置"：选择新目录后把现有数据完整迁移过去并更新引导文件，迁移前自动备份 | P1 |
| M0-8 | 数据目录自包含 | 数据目录内结构固定且全部自包含：<br>`data.db`（数据库）<br>`config.json`（全部设置）<br>`exports\`（导出的报告副本）<br>`backup\`（自动备份） | P0 |

**换电脑完整迁移流程（验收场景）：**

```
场景1（便携模式）：拷贝整个软件文件夹 → 新电脑双击 EXE → 直接运行，数据全在
场景2（自定义目录）：拷贝 EXE + 数据文件夹 → 新电脑双击 EXE
  → 首次向导 → 选"自定义目录" → 指向拷来的数据文件夹
  → 提示检测到已有数据 → 确认 → 完整恢复，设置/流水/报告全部在
```

### M1 定时提醒引擎

| 编号 | 需求 | 说明 | 优先级 |
|---|---|---|---|
| M1-1 | 可配置提醒周期 | 默认 50 分钟，设置范围 20–120 分钟 | P0 |
| M1-2 | 可配置活动时长 | 默认 5 分钟，范围 1–30 分钟 | P0 |
| M1-3 | 可配置工作时段 | 如 08:30–18:30，非工作时段不弹窗、不计时 | P0 |
| M1-4 | 午休免打扰 | 可设午休时间段（如 12:00–13:30），期间不弹窗 | P1 |
| M1-5 | 空闲检测暂停计时 | 键鼠无操作超过 5 分钟判定为离开，计时自动暂停；回来后"重新计时"或"继续剩余时间"可在设置中选择 | P0 |
| M1-6 | 锁屏不弹窗 | 系统锁屏/睡眠时暂停计时，唤醒后恢复 | P0 |
| M1-7 | 推迟无上限 | 用户明确：**推迟次数不设上限**；每次推迟时长可配置（见 M2-7） | P0 |
| M1-8 | 首次启动延迟 | 软件启动后 N 分钟（默认 10 分钟，可配）再开始第一个周期 | P1 |
| M1-9 | 演示/会议勿扰 | 检测到有应用全屏运行（共享屏幕、PPT 演示、看视频）时自动推迟弹窗，全屏结束后补弹；可在设置中开关（默认开） | P2 |

**计时逻辑：**

```
启动 → 等待首次延迟 → 开始计时(周期) → 到点弹窗
  ↓ 期间检测到空闲>5min 或锁屏：暂停计时
  ↓ 恢复：按配置"重新计时"或"继续剩余时间"
  ↓ 检测到全屏应用且勿扰开启：到点时自动推迟
弹窗关闭（任一按钮）→ 计时清零 → 开始下一周期
点"推迟" → 暂停周期，推迟时长后再次弹窗（不限次数）
```

### M4 日报 / 周报（AI 复制粘贴闭环）

**已定稿方案："提示词 + 数据一键复制 → 粘贴给任意 AI → 结果粘贴回软件保存"的闭环。**

理由：

1. **可靠性最高**：不依赖任何 API Key、网络、模型服务，永远不因为接口变动而坏掉。
2. **零成本零配置**：用户本来就用 AI（Kimi 等），复制粘贴是最稳定的路径。
3. **格式固定可控**：软件内置固定提示词模板，AI 输出格式约定为 Markdown，粘贴回来时软件只做保存和展示，不做脆弱解析。

| 编号 | 需求 | 说明 | 优先级 |
|---|---|---|---|
| M4-1 | 流水视图（原料） | 托盘菜单"查看今日"按时间轴列出当天流水，可编辑、删除、补录；"历史流水"按日期查询任意一天 | P0 |
| M4-2 | 报告视图（成品） | 托盘菜单"我的报告"按日/周归档展示已保存的日报/周报，可查看、再编辑、一键复制全文（提交钉钉/邮件） | P0 |
| M4-3 | **一键复制"日报提示词+数据"** | 点击后把固定提示词模板 + 当天全部流水（时间/标签/内容）按固定格式组装好复制到剪贴板，用户直接粘贴给 AI | P0 |
| M4-4 | **一键复制"周报提示词+数据"** | 同上，数据范围为本周全部流水 + 本周各天已生成的日报（如有）；周起始日（周一/周日）可配置 | P0 |
| M4-5 | **粘贴回导入** | 提供"导入日报"/"导入周报"对话框，一个大文本框，用户把 AI 生成结果整段粘贴进来，软件保存到 `report` 表并关联对应日期/周，同时在数据目录 `exports\` 下存一份 `.md` 副本；同期已有报告时提示"覆盖/保留两份" | P0 |
| M4-6 | 报告再生成 | 报告视图提供"重新复制提示词+最新数据"，流水改过后可重新走 AI 流程生成新版报告 | P1 |
| M4-7 | 原始数据导出 | 流水可导出 Markdown / CSV，可选日期范围（不经过 AI 的原始备份） | P1 |
| M4-8 | 久坐统计 | 当天/本周：提醒次数、活动次数、跳过率；该统计自动附在复制给 AI 的数据里，让 AI 写进报告 | P1 |

**内置日报提示词模板（软件自带，可在设置中修改）：**

```
你是一位嵌入式汽车软件工程师的日报助手。请根据下面的今日工作流水，生成一份正式的中文工作日报。
要求：
1. 按以下分类归组：【功能开发】【故障调查】【软件释放】【功能评估】【协助支持】【会议及其他】
2. 把口语化描述改为正式书面表述，保留技术细节（问题现象、定位结论、责任人、版本号）
3. 同类琐碎事项合并为一条，突出"问题-动作-结论"结构，体现工作量
4. 末尾附【明日计划】（根据今天未完成事项推断）和【今日久坐统计】
5. 只输出日报正文，不要其他解释

=== 今日工作流水（2026-09-14）===
09:20 [故障调查] 排查怠速抖动，定位为点火提前角标定问题，已反馈标定组
11:10 [软件释放] SWITCH 释放 ECU_SW_v2.3.1
...（此处由软件自动填充）

=== 久坐统计 ===
提醒 8 次，活动 6 次，跳过 2 次
```

**周报提示词模板**：结构同上，输入为本周流水 + 各天日报，要求输出按天汇总 + 本周重点成果 + 下周计划。

**表结构设计：**

```sql
-- 工作流水记录（原料数据）
CREATE TABLE work_log (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    log_date    TEXT NOT NULL,          -- 2026-09-14
    start_time  TEXT,                   -- 周期开始 10:00
    end_time    TEXT,                   -- 记录时间 10:50
    tag         TEXT,                   -- 快捷标签，可空
    content     TEXT,                   -- 记录内容，可空
    source      TEXT DEFAULT 'popup',   -- popup=弹窗 / manual=补记 / continue=续记
    continue_from INTEGER               -- 续记来源条目 id，可空
);

-- 提醒事件（久坐统计用）
CREATE TABLE reminder_event (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    event_time  TEXT NOT NULL,
    action      TEXT NOT NULL,          -- done=刚活动完 / skip=跳过 / postpone=推迟
    break_min   INTEGER
);

-- AI 生成的报告（成品数据）
CREATE TABLE report (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    report_type TEXT NOT NULL,          -- daily / weekly
    period_key  TEXT NOT NULL,          -- 日报: 2026-09-14 / 周报: 2026-W38
    content     TEXT NOT NULL,          -- 粘贴回来的 Markdown 全文
    created_at  TEXT NOT NULL,
    updated_at  TEXT
);
```

|---|---|

## 5. 边界与排除项（V1 不做）

- 不做屏幕录制、截图、窗口标题监控
- 不做番茄钟模式（用户明确不需要）
- 不做云同步、多设备、账号体系
- 不内置 AI API（一律走剪贴板闭环，保证可靠性和零配置）
- 推迟不做次数上限（用户明确）
- 不做自动更新（手动替换 EXE 即可）
- 手机端不做

## 附录 A：同类竞品调研结论（2026-09）

调研了主流的久坐提醒工具与日报工具，**结论：本软件的组合形态（久坐提醒 × 工作流水 × AI 日报闭环）目前没有现成替代品，值得自己做。**

| 产品 | 做了什么 | 与本项目的差距 |
|---|---|---|
| [Stretchly](https://github.com/hovancik/stretchly) | 开源休息提醒，短休息+长休息，自定义提示语，可严格模式 | 只有提醒，无工作记录；Electron 架构内存占用大 |
| [Workrave](https://workrave.org/) | 老牌 RSI 防护，微休息/休息限制/每日时限，带保健操指引 | 只有健康提醒，无工作记录 |
| [Pausr](https://pausr.io/blog/best-apps/time-out-stretchly-workrave-alternatives) | 商业化休息提醒，能检测会议/演示上下文推迟提醒 | 无工作记录；闭源付费（其上下文检测思路已被本项目 M1-9 吸收） |
| [standup-reminder](https://github.com/dxlcf/standup-reminder)（GitHub 开源） | Windows 单 EXE 久坐提醒，工作时段内弹窗、倒计时、延后一次、计分 | 与本项目 M1/M2 思路几乎一致，但**完全没有工作记录和日报功能**，可作为技术参考 |
| [ActivityWatch](https://activitywatch.net/) | 自动时间追踪（窗口标题/应用时长） | 自动采集但不知道"在做什么、结论是什么"，无法体现杂活工作量；与本项目互补而非替代 |
| [GitPulse](https://github.com/GoldenZqqq/GitPulse) | 从 git 提交生成日报/周报 | 只覆盖代码工作；本项目覆盖全部工作类型（含杂事） |

**从竞品吸收的经验：**

1. Workrave/Stretchly 都验证了"强制弹窗"是提醒生效的关键 —— 本项目全屏遮罩设计正确。
2. Pausr 的卖点是"会议/演示时不弹" —— 已补充为 M1-9。
3. standup-reminder 证明"Windows 单 EXE + 托盘 + 工作时段弹窗"这条技术路线已被走通，工程量可控。
4. 所有竞品都不解决"记录做了什么"，这正是本项目的差异化价值。
